---
name: Сценарии JUnit
description: Используй при написании и ревью Java UI-сценариев JUnit 5 по образцу Sprint_6.
---

1. Сформулируй наблюдаемый результат и дай тесту короткий `@DisplayName`. Группируй по функции: в Sprint_6 это `FaqTest`, `HeaderLogoTest` и `OrderTest`.
2. Готовь изолированную сессию через общую фикстуру, завершай через `@AfterEach`. Если задание требует двух браузеров, параметризуй браузер: базовый тест эталона запускает только Chrome. Предусловия пользователя готовь через API, кроме проверки самой UI-регистрации.
3. Запиши сценарий в порядке «предусловие → действие → проверка». В тесте вызывай методы страниц, а не `findElement`. Сверяй ожидание с фактом в этом же тестовом классе: например, `assertEquals(expected, page.getPasswordError())`. Повторяющуюся проверку можно вынести в именованный шаг тестовой фикстуры.
4. Для одного поведения с разными данными используй именованные параметризованные запуски, как `FaqTest.expectedAnswers`. Разные точки входа оставляй различимыми в отчёте.
5. Проверь, что Maven обнаружил все сценарии. В Sprint_6 Surefire ограничен `Mesto1Test`: такой фильтр скрыл бы UI-набор. Для Stellar Burgers полный прогон должен содержать 13 сценариев × 2 браузера без пропусков.
6. Для диагностики используй логер проекта, например `java.util.logging.Logger` в базовой фикстуре. Записывай браузер и имя теста; не выводи пароли и токены. Действия пользователя описывай через `@Step`, не дублируя каждый шаг в консоли.
